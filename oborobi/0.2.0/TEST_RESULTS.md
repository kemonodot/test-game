# 実行・視覚検証結果 — 0.2.0

実施日: **2026-10-10** / Godot **4.6.3.stable.official** / Debian Linux。

一本の鎖を敵・石垣・外周に掛け、巻き取りで高速移動し、途中解除後は慣性で滑走する検証版です。Godot上の機能検証は **69項目合格**。署名付きAndroid APKを作成しました。**Android端末でのインストール・起動・性能は未検証です。**

## 鎖・衝突と通し戦闘

`tests/grapple_check.gd`: **30 / 30合格、終了コード0**。[実行ログ](captures/android/grapple-test.log)。

- 壁への接続、加速、壁の手前での停止、狙い補助、移動する敵への追従。
- タップ解除時の速度保持と減速、接続先の敵が死亡した際の解除。
- 石垣による射線遮断、大きい時間差でも壁・外周・角を貫通しないこと。
- 高速で接触した敵への強襲斬撃、生き残った敵による進路の阻止。既に重なっている敵からは離れる方向へ移動できること。
- 敵の並び順にかかわらず手前の相手に接続。飛行中に敵が割り込んだ場合も接続先を更新し、外周の向こうの敵には接続しないこと。
- 刀が石垣を通り抜けず、追跡する敵が石垣を回り込むこと。
- 3乱数シードでの通常HP・威力の戦闘、経験値と成長、リザルト、オブジェクト上限。

## タッチ・中断・Android通知

`tests/input_check.gd`: **8 / 8合格、終了コード0**。[実行ログ](captures/android/touch-test.log)。

Godotの入力系へ `InputEventScreenTouch` / `InputEventScreenDrag` を送り、screen transformを使って実際のGUIと戦場を操作しました。

- 開始ボタンで戦闘へ進む。
- ドラッグして指を離すと一回だけ鎖が射出される。
- 短いタップで解除し、速度が残って実際に滑走する。
- システムによるタッチキャンセルでは射出しない。
- 停止・再開ボタン、Androidの戻る通知、アプリの背景移行による停止と指の解除。
- 背景からの復帰時に自動で戦闘を再開しない。
- 実際の3択カードを選ぶと能力が増え、戦闘が再開する。

タッチ由来の合成マウスイベントによる重複射出も防いでいます。通知と入力はGodot上の試験であり、Android OS上の試験ではありません。

## 性能と残る制約

- 録画中のゲーム更新p95は **2.681ms**、最大敵数23、最大破片数75。この値はGPU描画・録画処理を含まず、上限110体・520片の負荷測定でもありません。30fpsは動画の出力設定で、Android実機のFPSを保証しません。
- このクラウドには使用可能なKVM・CPUの仮想化支援がありません。以前のCPUのみの仮想端末検証でもAndroidのパッケージ管理サービスが安定しなかったため、APKのインストール・起動を確認できていません。実機での起動、FPS、発熱、ノッチやシステムジェスチャーとの干渉が残る検証項目です。
- 一本の鎖で直線的に引き寄せます。二本の鎖、振り子、壁への巻き付きはありません。鳥居・灯籠は装飾で、中央の石垣と外周が壁の当たり判定です。
- 低FPS時は大きい時間差を抑えるため、ゲーム進行が遅くなる場合があります。狙い補助・速度・滑走距離の実機調整が必要です。
- セーブや通信はありません。OSに終了された場合は新しいランになります。

GodotとAndroidツールチェーンの再現用セットアップ・ビルドは実行済み。TLSと公式アーカイブのチェックサム検証を保持しています。クラウド環境の起動手順は設定下書きへ保存しています。下書き保存は新しい環境の公開・実機動作確認を意味しません。
